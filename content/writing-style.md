## 喜欢（怎么开头、怎么走、怎么收）

1. 开场直接给「事情」：一个具象场景或动作，不设宏大背景。
   例（blog humanized）：`同事发来一个 Word 文档，你把内容复制进笔记或编辑器，标题变乱码、表格散架、图片失踪。`
2. 工具 / 事件一句话说清：`它就是个"文档翻译器"，办公格式进，干净 Markdown 出。`
3. 先给结论和命令，再解释原理：MVP 先行（`先跑通再说`），架构后置。
4. 边界诚实：官方声明与独立实测分开写（`官方宣称的速度我没有独立测过`；`数据会变，star 数是检索时刻快照`）。
5. 收尾给可执行动作 + 时间承诺：`拿一份手边文档跑一次，三分钟知道值不值。`
6. 幽默克制：降格式（`排版像被洗衣机搅过`），笑点落下后不解释。

## 不喜欢（禁用 / 少用）

1. 宏大开场：`随着…`、`在当今…`、正确废话铺垫。
2. 空泛评价：`体验很好 / 效率提升 / 很重要` 必须换成数字、动作或具体结果。
3. 检测率 / 流量承诺：不承诺过检测、不写必火类话术。
4. 编造亲历：没有素材用 `【经历占位：…】`，不为了人味补一段没发生过的经历。
5. 金句拖尾：总结段、`综上所述`、强行升华。
6. 均匀结构：三项强制排比、段落等长、句长接近的流水线节奏。

## 场景口径（同一事实在不同平台怎么说）

- **公众号 / 深度稿**：场景开场 → 小白 MVP → 由简入深 → 模块/架构 → 坑点 → 下一步；允许口语转折，段落 3–5 行。
- **X 短链**：倒金字塔，第一条直接给痛点，最后一条给动作；官方口径与实测边界分开表态。
- **小红书**：痛点开场 + 三条入口列表 + 诚实边界 + 行动收尾；emoji 克制，配文短句。
- **口播**：按气口断句，前 3 秒给事件，命令完整念出，最后落一个动作。

## 事实边界

- star / forks / 日期一律标「截至检索时刻」，并带更新说明。
- 官方 README 声明标「官方宣称 / 文献口径」，不升级为独立实测。
- 个人经历、失败细节只写用户提供过的事实；缺失用占位，禁止补虚构。
- 引用必须带回链来源；不补虚构出处。
