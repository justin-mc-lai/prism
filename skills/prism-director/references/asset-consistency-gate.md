# 资产一致性门（distill · MAP-017）

> 蒸馏源：`vendor/skills/drama-skills/skills/short-drama-assets`（MIT，identity/variant/
> continuity 框架）+ alibaba/lumenx README（MIT，资产三件套与全片画风统一）。
> 只取判断框架，不复制运行时；执行契约见 `contracts/asset-consistency.contract.md`。

## 1. 三分法（每个画面实体先归类再动笔）

| 类 | 定义 | 归属 |
|---|---|---|
| **身份** | 换一个就不再是同一个人/地/物 | 资产层：Character+Look / Location+View / Prop+State |
| **变体** | 身份不变，状态改变（服装/伤势/时段/天气/开合/持有） | 资产层：记基底+变化+原因+生效范围 |
| **镜头瞬态** | 姿势、视线、左右手、站位、相机角度 | 分镜层拥有，资产层只引用 |

禁止把每次出场都变成新身份；含混指代标「未决」，**不猜**。

## 2. 识别锚点

每项身份写最小可识别设定：可见、可生成、可比较；不用空泛质量词（"精致""高级"）
替代事实。lumenx 对应物：角色三视图、场景定调图、道具参考图——锚点即参考图的可核对事实。

## 3. 边界匹配（CON-01）

相连镜头逐字段比较前一镜已接受的**结束状态**与下一镜已接受的**开始状态**；
差异必须有上游变化记录支撑，禁止靠运动/生成提示词悄悄"补过去"。

## 4. 变化记录不变量（CON-04）

每条变化必含：前态 → 后态、原因/来源、生效范围、受影响的现有 ID。
没有变化不得只写"更新了"；剧本修订后按依赖标记 stale，不重做全项目。

## 5. Binding gate（AST-05）

所有下游引用必须解析到明确身份条目；**未决项不得流入图片提示词或分镜**
（fail-closed，不是警告）。

## 6. 画风统一（lumenx 蒸馏）

项目级风格锚点帧先行（Lookdev）：全片分镜/生成 payload 引用同一风格锚点；
换风格 = 新建风格版本并记录生效集数，禁止逐镜漂移。

## 7. manga_drama 落地映射

- storyboard.json 角色卡 + asset_ref → 必须解析到 assets/ 身份条目（AST-05）
- 镜头 start/end 字段 → CON-01 边界匹配对象
- assets/ 目录 → 身份条目 + 变体记录 + 风格锚点帧存放处
- QA 判据升级：refs 存在 ≠ 通过；须过本门 §1–§6

## 8. 与资产提示词模板的关系

本门管「抽出来之后**跨镜是否一致**」；**资产 ref 提示词怎么写**见
`asset-prompt-templates.md`（7 段 identity block + 五类资产卡 + 风格正交 + 自查清单）。
两者叠加：先按模板出 ref 图（中性平光、身份块逐字复用），再由本门做跨镜核对。
模板自查未过的 ref 不进资产库，更不进分镜（fail-closed，同 AST-05）。
谱系/尺寸冻结方法论见 `asset-lineage-scale.md`（LIN/SCL），由契约判据 7–8 强制执行。
