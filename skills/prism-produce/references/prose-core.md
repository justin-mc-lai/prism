## 五原则（执行版）

### 1. 像说话一样写作

- 写完后**朗读**：拗口、像领导讲话、像产品发布会稿 → 改短句、加口语连接词（「说白了」「更难受的是」偶用即可，别堆）。
- 允许一句半成型想法，但别跑题。
- 禁止：「综上所述」「值得注意的是」「不可或缺」「正如我们所见」「被广泛使用」「基于……的原因」。

### 2. 一句话只讲一个意思

| 删 | 改法 |
|----|------|
| 非常、极其、显然、至关重要 | 直接删，或换具体数据 |
| 不仅……而且…… / 既……又…… | 拆成两句 |
| 深入探讨、不断演变的格局 | 讨论 / 变化 |

### 3. 倒金字塔

**深度稿：** H1 + 一句话收益 → 元信息行（可扫读）→ 场景段（痛点）→ 是什么 / 怎么工作 / 怎么用 → 对比表、命令块、踩坑 → 收尾行动。

**日榜：** 今日涨星合计 + 一句话主线 → 截图 → 全表（中文白话列）→ 三条深挖 → 下一步。

### 4. 主动语态

| 弱（被动/绕） | 强（主动） |
|--------------|-----------|
| 新模型被 OpenAI 发布 | OpenAI 发布了新模型 |
| 配置需要被完成 | 你要配好 APP_ID 和 SECRET |
| 被认为是最优解 | 很多人用它解决 XX 问题 |

### 5. 正面表述

| 避免 | 改为 |
|------|------|
| 这不是又一个 XX | 它是 YY（直接说定位） |
| 别指望 ZZZ | 适合 AA 场景；BB 场景建议另选 |
| 不要以为…… | 你可以把它当成…… |

对比表「你以为 / 实际上」**最多 1 张**，且用于纠偏，不用于全文结构。

## 节奏

- 段落 3～5 行；一节一个主题。
- 连续三句长度相近 → 打断其中一句。
- 列表项 >5 条且每条 <10 字 → 改段落叙述。

## 新手小白读者层（默认假设与写法）

默认假设：会用浏览器、能复制粘贴命令、知道 GitHub 是放代码的网站；
不假设：读过源码、熟悉 agent 工具链、每天写代码。

写法：

1. **先痛点后名词**：「改需求 AI 直接改一堆文件」先于「Spec 驱动开发」。
2. **类比一句**：「像装修前先画施工图」；类比后立刻收，不堆。
3. **术语 inline**：「CLI（命令行工具）」；禁止独立「名词大全」节。
4. **命令从简**：深度稿最多 1 个「能跑通」示例 + 安装表可保留。
5. **🗺️ 段**：用「谁调谁」白话，附路径给想深挖的人。
6. **⚠️ 段**：明确「你可以跳过这篇如果…」。

## 库拾专用

- 深度稿：slash 命令集中在「怎么上手」一节，不要全文 `/ce-*` 小标题。
- 日榜：表格描述列必须中文白话，禁止贴英文 README 摘要。
- 开源解读：先讲「解决谁的什么问题」，再 star / 目录结构。

## 深度管线（oss-pick-standard 顺序）

```text
notes.md → MASTER.md + meta.yaml → repo-digest.md（必须读仓）
  → humanized.md 初稿 → visual-enrich（assets/ + 图说，≥2 张）
  → humanize 终检 → render → publish（人工批准）
```

日榜不读仓、不跑四段式（见 `oss-daily-archetype.md`）。

## Readability 门（R10 蒸馏 · 规则层）

> 规则蒸馏自源仓 readability-lint.py（自研无 license，不 pin 脚本）；
> Prism 原生实现：`python3 scripts/check_readability.py <稿> [--depth]`。

### 必查项（命中即改）

1. 禁止标题/行内出现内部公式标签：「总（」「分（」字面标题、「总（30 秒」「分（读者」「总（收尾）」。
2. 四段式体裁（--depth）必含四段 H2（一句话看透本质 / 核心架构与主流程 / 绝妙的设计亮点 /
   潜在坑点与局限性）+ 入口段（小白 MVP / 由简入深）；缺段即不合格。
3. 禁翻译腔四件套：正如我们所见 / 被广泛使用 / 基于以下原因 / 基于……的原因。
4. AI 填充短语计数 ≥3（值得注意的是 / 此外，/ 至关重要 / 深入探讨 / 不仅 / 而且）→ 删。
5. 弱修饰词计数 ≥4（非常/极其/显然）→ 删或换具体数据。
6. 被动暗示（被…发布/完成/实现/采用）→ 改主动。
7. 英文泄漏：整行无中文且含 ≥4 个英文词且无技术白名单令牌 → 未翻译句子，改白话。

### 体裁判定

- blog/深度稿：`--depth` 严格模式（四段式结构完整）。
- thread/xhs/口播：结构段检查不适用（形态契约已定结构），只跑通用项。
