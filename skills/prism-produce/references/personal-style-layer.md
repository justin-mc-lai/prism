# 个人文风层（personal-style-layer · Prism 蒸馏版）

> Internal reference for `prism-produce`. Not host-discoverable.

> （X Article，2026-08-17，https://x.com/ai_Goge/status/2089141768461902033）。
> 位置：produce 侧第三道门——prose-core 定底线 → human-voice-prose 定人味 →
> humanize-techniques 定句式 → 本层定「像谁」。随后才进 prism-qa 的 anti-slop-gate。
> 对应 MAP-011 的 style-transfer essentials 蒸馏方向（recurrency 通过后落地为参考层）。

## 第一性原理

去 AI 味的终点不是检测分数，而是「作者信息密度 + 可识别的个人判断」。
AI 能写公共知识；只有作者知道：用了几天、哪里失败、花了多少钱、哪个版本最好用、
关掉了哪个功能、原来怎么看、后来为什么变、客户真正抱怨什么、哪一步最浪费时间。

所以本层不解决「不像 AI」，解决「像谁」。若文章没有作者自己的信息与判断，
换再多句式也只是把公共文本重新排版。

## 个人文风文件（WRITING.md / style.md）

跨篇默认路径：`content/writing-style.md`（作者自有，user-authored，不进 public surface）。
单篇覆盖：`content/masters/<slug>/style.md`，只在单篇战役内生效。

文件内容按实际作者写，不预设模板；最少包含：

| 块 | 写什么 |
|---|---|
| 喜欢 | 开头方式、句长偏好、举例习惯、怎么下判断 |
| 不喜欢 | 禁用的句式、词、结构（可直接引用 human-voice-prose 禁令） |
| 场景口径 | 同一事实在公众号/小红书/X/口播/论文里分别怎么说 |
| 事实边界 | 哪些信息不能编、哪些数字必须核对、引用怎么处理 |
| 学习记录 | 每条规则来自哪次修改（日期 + 稿件 + diff 证据） |

没有 style 文件不阻断：用冷启动流程先建，或者本轮只用材料门 + 人味层兜底，
并在 human card 写明「个人文风层未启用」。

## 冷启动：从真实样本提取

1. 收集 10～20 个作者自己写过的样本：邮件、旧文、X 帖、聊天、公众号。
2. 只统计，不发明：句长区间、开头方式、寒暄习惯、表达不同意见的方式、
   常用词、永不使用的词。
3. 把统计结果写成 style.md 的「喜欢 / 不喜欢」两块，并标注样本来源。
4. 以后每篇成稿前让 agent 读 style.md；成稿后人工改，改完进学习循环。

## 修改学习循环（核心增量）

每完成一次「AI 初稿 → 人工修改」：

1. 对比两版差异（`diff` 或肉眼），只提取**重复出现的修改意图**，不逐字回写。
2. 一条修改意图形成一条规则，写进 style.md 的「学习记录」，
   必须带：日期、稿件路径、一句证据（作者把什么改成了什么）。
3. 规则数不设上限但设门槛：同一条意图出现 ≥2 次才固化；单次修改不固化成规则。
4. 规则与 human-voice-prose 硬禁令冲突时，硬禁令优先；style 规则不得豁免事实边界。

边界：学习记录是 produce 侧 advisory，不是 truth/gate 判定依据
（对应 Beacon learning 边界）；qa 只核验终稿与 style 的冲突，不替 style 文件背书。

## 作者信息密度（收尾前过一遍）

成稿前（或 qa 前）用「只有作者知道」清单补最后一层，能补就补，不能补就保留占位：

- 实际用了几天 / 在哪里失败过 / 花了多少钱
- 哪个版本 / 哪个功能最后关掉了 / 哪个参数改了才生效
- 原来的看法 → 后来为什么变
- 客户/读者真正抱怨过什么 / 哪个步骤最浪费时间

硬规则：没有素材就用 `【经历占位：…】`，禁止为了人味编经历；
「增加人味」永远不能以「新增未核实事实」为代价（与 anti-slop-gate §1 一致）。

## 场景口径

同一事实在不同场景允许不同表达（蒸馏自 shuorenhua 思路），
但事实本体不变。场景档位沿用 anti-slop-gate「场景档位」表；
本层只要求：style.md 若写了场景口径，成稿须落在该口径内，不能跨场景混腔。

## 硬边界

- 不承诺「必过朱雀 / 0% AI」；检测分数不是本层目标
- 不编经历、不补虚构案例、不为像真人破坏语体（论文不得口语化）
- 不把 style.md 当作事实来源：它只约束表达，不新增事实
- 不自动发布；发布仍走 prism-release 人工批准

## 收尾自检（produce 侧，进 qa 前）

1. 换一个模型也能原样写出这段吗？→ 补作者信息密度或删
2. 有 style.md 吗？终稿与「喜欢/不喜欢」冲突吗？
3. 这篇文章里有没有只有作者才知道的东西？没有 → 这是公共文本的排版
4. 有没有为像真人编的经历？→ 有则删，回到材料门
5. 念一遍：这句像作者会说的话吗，还是像「换个人也这么说」？
