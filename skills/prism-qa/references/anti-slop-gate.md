# Anti-Slop Gate（Lake D1 · distilled）

> QA 侧门禁。maker ≠ checker：本文件只做核验，不代写作侧改写事实来放行。
> Source: no-ai-slop / humanizer-zh / selfmedia-humanize（MAP-005 distill）

## 核验方式

每一条 finding 必须：

- 引用原文行（quote 具体句子）
- 给出修复建议（一句话）
- 写证据路径（`.beacon/evidence/qa-feature/prism-form-writing-v1/...`）

缺原文行或证据路径的 finding 不算数；缺证据默认不过。

## Slop 模式清单（≥15 条）

- 二元对比："这不是 X，而是 Y"；直接说 Y
- 清嗓开场："这里有个关键点""坦白说""我想说清楚"；删掉直接给观点
- 伪洞察设置："大多数人忽略的是…""没人告诉你…"；去掉包装，让主张自立
- 冒号揭晓：名词短语 + 冒号 + 小写戏剧揭示；改普通陈述句
- 浅层 -ing 分析："highlighting""underscoring""showcasing" 假装解释意义
- 重要性吹捧："标志着里程碑""扮演关键角色""彰显意义"；陈述事实即可
- weasel 归因："专家认为""研究表明""普遍认为"；点名来源或删除
- 假强动词：能说 is/has 就不用"serve as""act as"
- 同义词轮换：为避重复乱换词；清楚就重复
- 否定列举："不是 A。不是 B。是 C。"；直接说 C
- 戏剧性碎片："就这。这就是全部。"；用完整句
- 机械节奏：句式等长、段落同构、连续短句堆砌
- 修辞设问："如果我告诉你…""你猜怎么着"；直接给答案
- 假深刻结尾：结尾金句是漂亮比喻/格言；删掉，用最具体的句子收尾
- 总结复读："综上所述""最后""总体而言" 加复读段落；读者刚看完
- 格式 slop：标题 emoji 滥用、句中加粗、两句话也开小节、列表代替散文
- 破折号滥用：短稿零破折号；长稿 1–2 个以内
- 三段式法则/机械排比：三连结构当默认节奏
- 填充短语：开场白与强调拐杖词（"值得注意的是""赋能""闭环"）
- 空金句：听起来可引用但无信息增量
- 意义夸大：作为/标志着/见证了/是…的体现/为…奠定基础（陈述事实即可，见 humanizer-zh 模式 1）
- 知名度吹捧：独立报道/由知名专家撰写/活跃社交媒体（列出来源不提供上下文）
- 浅层 -ing/进行式分析：highlighting/underscoring/showcasing 假装解释意义（中文对应「凸显/彰显/象征着」）
- 宣传广告腔：坐落在…令人叹为观止/必游之地/充满活力的/丰富的文化遗产（中性陈述即可）
- 模糊权威归因：行业报告显示/观察者指出/专家认为/一些批评者认为（点名来源或删除）
- 提纲式挑战段：「尽管…面临若干挑战…」公式段（改成具体事件与后果）
- 系动词回避：作为/代表/充当 [一个]、拥有/设有/提供 [一个]（能用「是/有」就直接写）
- 否定式排比：不仅…而且…、这不仅仅是…而是…（拆成一句正面陈述）
- 三段式法则：强行把想法分成三组显得全面（两项为限，第三项换说法或删掉）
- 过度强调语：极其重要的/核心的/关键性的作用/时刻（删修饰，留事实）

## 场景档位（蒸馏自 shuorenhua）

改写前先判场景，场景决定档位与改动下限：

| 场景 | 信号 | 默认档位 |
|------|------|---------|
| chat | 短回复/日常对话/评论 | minimal（只清最硬的） |
| status | 站会/进度同步/复盘摘要 | minimal–standard |
| docs | 操作文档/技术说明/FAQ | minimal（术语稳定优先） |
| public-writing | 公众号/小红书/对外文章/观点写作 | standard |

- 档位只描述「最低清理量」，不描述改写力度；命中硬模式仍要处理。
- 误杀防护：引用原文、命令、接口名、字段名、日志、报错、系统主语、技术报告术语默认保留。
- 无源引用三选一：`rewrite-safe`（去掉引用后论断能独立成立才保留）/ `audit-only`（指出缺来源，不补写）/ `rewrite-with-placeholder`（用户明确要保留骨架时写「有研究认为…，但这里没有给出处」）。禁止补虚构来源。
- 中英混排句中的英文词按实际语义判断，不机械套词表。

## 仲裁顺序（蒸馏自 qu-ai-wei）

所有规则冲突时按序仲裁，序号小的胜出：

| 优先级 | 约束 | 一句话 |
|---|---|---|
| §1 | 不发明事实 | 终稿里的数字/事件/人物/引用，原文都要能打钩；打不到 → 删除或标「请核对」 |
| §2 | 真人停手门检 | 输入是真人写的 → 只清格式，不动语言；误改真人口吻比残留 AI 腔更严重 |
| §3 | 语体降级保护 | 改写终稿跟原文语体档最多差一档；跨档先问场景 |
| §4 | 过度消毒反制 | 终稿至少留一处毛边（主观判断/具体感受/圈层语境），不能改成无菌中性散文 |
| §5 | 减法规则 | 按模式清单做减法；白名单是硬例外 |
| §6 | 打磨抬升 | 弱动词/机关枪节奏/filler/弱化细节/倒装语序/跨档语体——看到就改 |

仲裁示例：减法要删某词但删掉就没毛边了 → §4 胜出保留；打磨想把「速度提升」改成「快了 3 倍」但原文没数字 → §1 胜出放弃。

## 停手门检（真人文本）

命中任何一条强信号，优先判「不改」：自纠/犹疑/填充语气词（「我忘了」「我猜啊」）；浓厚地域词/方言（北京儿化、东北「整」、川渝「巴适」、粤语「嘅喺」）；meta-irony/自嘲（「用比较酸的话说…」）；具体到只有这个人/这件事的细节；可辨识作家口吻（金庸/王朔/汪曾祺/阿城等）；访谈/对话实录特征。

判断不准时宁可判「真人」不改。门检必须显式输出判断声明：【门检】判断：AI 生成文本 | 证据：[≤2 条具体信号]，或【门检】判断：真人文本，本门只清格式。

## 人话判据（≥5 条）

- 句式长短交错：长句 + 短句 + 反问 + 感叹；拒绝句句等长对称
- 口语转折是点缀不是灌满：其实/说实话/讲道理/话说回来，禁止每句一个
- 具体细节优先：时间、场景、结果越具体越好；无素材用占位，禁止假履历
- 情感起伏：有态度、犹豫、取舍；不要只有正确废话
- 反模板：少机械排比、少空口号结尾
- 通读出声不别扭

## 硬边界

- 不承诺「必过朱雀 / 0% AI」——检测模型会变，只能降模板感
- 不编造个人经历、数据、截图；无素材用 `【经历占位：…】`
- 不教批量刷检测、伪造账号或恶意规避平台规则
- 为降 AI 味不得把稿子改到不可读
- 不为降 AI 味删除信息：数字修饰对象、主体与动作/目标的配对关系必须保留；抽象信息不得擅自具体化

## 放行条件

- 所有命中模式都有 原文行 + 修复建议 + 证据路径
- 人话判据逐条通过或有显式豁免理由
- 个人文风一致性：存在 `content/writing-style.md` / 单篇 `style.md` 时，终稿与其「喜欢/不喜欢/场景口径」不冲突；冲突处给原文行 + 修复建议（style 只约束表达，不新增事实）
- maker 不自证：produce 侧 evidence 与 qa 侧 finding 分离
